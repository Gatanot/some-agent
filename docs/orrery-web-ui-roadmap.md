## 2. 当前实现与缺口

代码入口：[服务端](../packages/web/src/server.ts)、[页面](../packages/web/index.html)。

| 能力 | 当前情况 | 下一步 |
| --- | --- | --- |
| 本地启动 | Node HTTP 服务，仅绑定 loopback；开发模式由 Vite middleware 提供页面 | 完善启动失败、退出和生产静态资源说明 |
| Agent 接入 | 服务端创建并复用当前 SDK session；页面接收版本化 SSE 快照和 agent 事件 | faux provider HTTP/SSE 覆盖流式思考/文本、工具 partial/error、取消、重连和 session transition；Chromium 中验证 prompt 和快照渲染 |
| 会话 | 侧栏通过 `/api/sessions` 显示真实历史 session，搜索、选择恢复和新建调用真实服务端；运行中禁止切换；命名走 `/api/session/name`；草稿按 session id 隔离 | 补分支和更细的恢复错误反馈 |
| 提交与取消 | `/api/prompt`、`/api/abort` 已接入真实 session；流式进行中提交按 steer 排队，草稿保留 | 补浏览器流程和跨标签页验收 |
| 更新传输 | 首帧/重连发送完整快照；流式事件只发增量字段，队列积压时合并为单帧快照 | 已完成；后续按需评估 WebSocket |
| 消息展示 | Svelte 时间线使用安全 Markdown、代码语法高亮、diff 呈现、代码复制和 thinking 折叠；工具卡片展开状态持久化 | 已完成；后续按需补更多专用工具呈现 |
| 页面状态 | 已接入真实初始化、运行中、停止中、错误、重连和无模型状态；模型与 thinking 选项来自当前 `ModelRuntime`；无快照时只显示连接状态 | 完善无模型配置入口和压缩状态 |
| 验证 | `npm run check`、Web 22 项测试和生产构建通过；Chromium faux-provider 流程覆盖选模、thinking、重命名、Markdown、代码复制及桌面/390px 布局 | 补键盘/焦点审查、取消和 session 恢复的浏览器操作 |

当前页面已经接入第一版真实状态，不再将 SSE 视为完成 token 级渲染。服务端首帧/重连发送完整快照，流式事件只发送 `WebSnapshotDelta`（流式消息、工具执行、排队消息等增量字段），发送队列积压时合并为一帧完整快照而不是断开连接。客户端按帧合并渲染，提交后的消息映射做缓存，流式 token 只重建当前消息；刷新或重连后从完整快照恢复。

此前记录的全量检查现已补跑；Chromium 流程使用 faux provider，不会向真实模型发送请求。

## 3. 设计方向

当前页面参考 `ref.png` 的本地编码工作台结构：左侧窄导航 rail、真实 session 侧栏、中央时间线和右侧 Changes / Terminal / 项目用量 检查栏。视觉使用低饱和深色背景、清晰边界和荧光黄绿色状态强调。

设计约束：

- 页面只渲染服务端当前 session 的真实内容，不内置固定会话、固定消息、模拟工具或演示状态切换。
- 没有首个 SSE 快照时只显示连接状态；没有历史消息时只显示真实空 session 状态。
- 用户消息、assistant 文本、thinking、toolCall、toolResult 和错误均从 agent 消息或事件快照转换而来。
- 右侧检查栏只显示真实工具结果；没有对应内容时显示空状态，不用示例代码填充。
- 侧栏新建、输入和停止均调用真实 API；布局切换只改变页面结构，不改变 session 数据。

验收：启动页面后可以看到当前 session 的真实内容；输入、工具执行、刷新、停止和重连都反映真实 agent 状态，不出现固定演示内容。

### 当前交付

- 入口：`npm run web`，默认地址 `http://127.0.0.1:3210`。
- 技术：`packages/web` 使用 Svelte + Vite；服务端使用 Vite middleware 提供开发页面，agent API 仍由同一 Node HTTP 服务承载。
- 布局：默认四栏工作台；窄窗口收起 rail 和检查栏，侧栏转为抽屉。
- 内容：当前 session 标题、路径、消息、工具结果、运行状态和上下文指标均来自服务端快照。
- 验证：Web 22 项测试、`npm run check`、无 Svelte 警告的生产构建均已通过；Chromium 在桌面和 390px 窄屏验证选模、thinking、命名、Markdown/复制、HTML 转义和无横向溢出。

## 4. 实现阶段

### P0：修正 MVP 的行为基础

- [x] 接入流式 message、thinking 和工具 partial output，刷新页面后能恢复当前运行视图。
- [x] 修复并发状态：重复请求、解析失败或另一标签页的请求不能错误清除正在运行的状态。
- [x] 为创建、恢复、运行、取消建立一致的生命周期；替换 session 前检查忙碌状态。
- [x] 新会话初始化失败时保留旧 session，关闭时结束运行、解除订阅并关闭 SSE 连接。
- [x] 限制请求体大小，校验端口和工作目录，区分输入错误与内部错误。
- [x] 保留 loopback 绑定，并检查 Host / Origin，避免其他网页触发本机 agent 操作；不引入账号系统。
- [x] SSE 增加心跳、断开清理和慢连接处理；首次连接与重连发送一致快照。
- [x] 修复提交失败后草稿丢失、按钮不可用等反馈问题。
- [x] 明确 workspace 依赖和启动流程，确保干净安装后可运行，不依赖偶然存在的 dist。
- [x] 补启动说明、已知限制和适合本地执行的测试入口。
- [x] 接入真实历史 session 列表、搜索、选择恢复和新建；运行期间禁止替换 session，session 切换过渡期也拒绝新的 prompt/abort。
- [x] 增加 session 命名接口和浏览器端按 session id 隔离的草稿。
- [x] 使用真实 `AgentSession` 和 faux provider 补 HTTP/SSE 流式思考/文本、工具 partial/error、prompt failure、取消、重连和 session transition 测试。
- [x] 在 Chromium 中验证 prompt、选模、thinking level、命名、Markdown/复制及窄屏布局；API 测试覆盖取消和 session transition。

验收：单个浏览器及个人多个标签页下，重复提交、断线、取消、新建失败均不会破坏 session 状态。多个标签页属于个人使用的健壮性场景，不引入用户体系。

- [x] 工具调用与结果关联、通用工具卡片、运行中/错误状态和 edit 结果的 diff 呈现。

- [x] 稳定滚动、回到最新；工具卡片展开状态持久化。

### P2：编码任务的审阅体验

- [x] 文件变更摘要与 diff 详情；区分工具结果中的 diff（时间线工具卡片）和整个工作区的 Git diff（检查栏 Changes）。
- [x] 长输出的展示层折叠/截断、展开与复制（快照与 session 仍保留全文）；虚拟滚动按实测结果决定是否引入。
- [ ] 会话内搜索与消息定位。
- [x] 检查栏项目用量视图：最近 14 天按天和按模型的 token 统计，无消耗的模型不显示；服务端通过 `/api/usage` 汇总本项目窗口内的 session 用量，并在每轮任务结束后自动刷新。
- [ ] 图片/文件输入，显示实际发送的内容和限制。
- [x] 运行中提交排队为 follow-up：输入栏有内容时只显示发送图标，提交后在当前任务结束后执行；输入栏为空时只显示停止图标。
- [ ] session tree、fork 和分支导航。
- [ ] 扩展通知、选择、确认、输入请求的 Web 适配。

验收：分支和会话操作遵循底层语义；切换会话分支不会被表述成回滚磁盘文件。扩展需要用户输入时不会静默卡住。

### P3：按实际使用反馈选择

- [x] 浅色/深色主题：默认跟随系统，可手动切换并记住选择；其余个人界面偏好待定。
- [ ] 项目快捷切换及跨项目历史检索。
- [ ] 更完整的扩展 UI 能力约定。
- [ ] 会话导出和分享用的静态文件。
- [ ] 更好的移动端阅读与简单输入。

不预先承诺：内置代码编辑器、完整终端、桌面壳、Git 自动回滚、插件市场。这些能力需要独立价值判断。

永久排除：多用户、组织、角色权限、租户隔离、团队协作、计费平台。

## 5. 实现约束与验证

- 复用 agent 运行语义和持久化，不在浏览器建立第二套 agent loop。
- 暂时保留 HTTP + SSE；只有明确需求出现才切换 WebSocket。
- PiServer / PiClient 仍是后续可评估的协议基础，不为了架构完整性提前迁移。
- 页面拆分为导航 rail、真实会话侧栏、时间线、内容 renderer、右侧检查栏和输入区，避免继续扩展单个 HTML 文件。
- 页面不携带固定演示数据；测试中的快照 fixture 只用于验证消息转换，不作为 UI fallback。
- API key 留在现有服务端配置中，浏览器仅接收显示所需数据。
- 工具输出按不可信文本处理；Markdown、链接和 diff 不得执行其中的脚本。
- 长输出的折叠/截断只影响浏览器渲染；快照、session 和复制内容都保持完整原文。
- 单用户不影响对取消、并发请求、跨站请求和恢复失败的基本正确性要求。

验证分为三层：

1. 使用真实 session 快照验证消息、工具、空状态、错误和重连渲染。
2. 使用假 provider 验证流式输出、工具更新、失败、取消和恢复；自动化不调用付费模型。
3. 按仓库规则运行相关测试和 `npm run check`；手工验证键盘输入、滚动、刷新和重连。真实模型验证单独记录，不以接口启动通过代替。
