# Orrery Web UI：页面与交互设计

状态：P0 实时工作台可运行，页面结构参考 `ref.png`；布局、配色和交互仍可根据实际 session 使用继续调整。

本文维护产品范围、页面结构和交互规则。阶段任务、当前缺口及验收标准统一维护在 [开发路线](orrery-web-ui-roadmap.md)中。

## 1. 已确定的范围

- 永远只有个人使用，不设计多用户、账号、角色、租户、协作或组织管理。
- Web UI 是 Orrery 的个人编码工作台，复用现有 agent、工具和 session 存储。
- 默认本机运行。当前入口为 `npm run web`，地址为 `http://127.0.0.1:3210`。
- 当前用 `PI_WEB_CWD` 指定工作目录、`PI_WEB_PORT` 指定端口。
- 先仔细设计页面，再继续实现功能。本文中的布局、配色和交互属于建议，尚未定稿。
- 本文专门记录 Web UI；已有 [Extension/TUI 路线图](orrery-extension-tui-roadmap.md) 中“终端为主要产品表面”的定位不限制本次 Web UI 开发。

## 2. 页面首先要回答的问题

打开页面后，应当能快速回答：

1. 我正在操作哪个项目、哪个会话？
2. Agent 正在回答、执行工具、等待我，还是已经结束？
3. 它做了什么，修改了哪些文件，哪里失败了？
4. 我在哪里继续输入，怎样停止当前任务，怎样恢复之前的工作？

默认视觉重心是对话和任务进展。模型参数、usage、原始 JSON 等信息按需展开，避免占据主要阅读区域。

## 3. 推荐的页面结构

参考 `ref.png`，默认使用四栏本地编码工作台：左侧导航 rail、当前项目的 session 侧栏、中央对话时间线、右侧任务检查栏。检查栏提供 Changes（Git）、Terminal（命令记录）、项目用量三个视图；没有真实结果时显示空状态。

```text
┌────┬──────────────┬──────────────────────────┬──────────────────┐
│ rail │ Sessions     │ 当前 session             │ Changes          │
│      │ 当前项目     ├──────────────────────────┤ Terminal         │
│      │ 当前任务     │ 用户 / Orrery 时间线     │ 项目用量         │
│      │              │ 工具执行与结果           │                  │
│      │              ├──────────────────────────┤                  │
│      │              │ 输入区                  │                  │
└────┴──────────────┴──────────────────────────┴──────────────────┘
```

### 布局建议

- 导航 rail 约 56–64px；session 侧栏约 250–280px；检查栏约 340–380px。
- 中央正文最大宽度约 760–880px，代码和工具输出可在右侧检查栏查看。
- 输入区固定在中央主区底部；长草稿达到上限后在输入框内滚动。
- 正文采用纵向时间线。用户消息以轻量底色或边线区分，避免大量左右气泡浪费代码阅读空间。
- 工具详情在时间线内保留调用上下文，文件变更和终端输出可在右侧检查栏集中查看。
- 中小窗口隐藏检查栏；窄窗口收起 rail，session 侧栏转为抽屉。

### 视觉建议

- 深色与浅色共用同一套语义 token；首次打开跟随系统偏好，顶部按钮可手动切换并记住选择。
- 使用低饱和深色背景、清晰边界和少量荧光黄绿色强调色，参考 `ref.png` 的工作台层级。
- 正文使用易读字体，代码、路径和命令使用等宽字体。
- 状态同时使用文字或图标表达，不能只靠红绿颜色。
- 避免大面积装饰、发光边框、每条消息一张厚重卡片和持续跳动的动画。
- 动效只用于说明展开、加载等状态变化，并尊重减少动态效果的系统偏好。

## 4. 核心交互设计

### 4.1 会话与项目

- 顶部始终能看到当前项目和会话名称；完整 cwd 按需查看。
- 首期在启动时固定项目目录，侧栏列出该项目的真实历史 session；选择 session 会恢复对应的服务端上下文。
- 侧栏搜索同时匹配会话名称、首条消息和整段 user/assistant 文本；命中时显示片段与命中次数，选中后恢复该会话，不在浏览器重建第二套检索。
- 明确区分“新会话”和“恢复会话”，不让刷新页面隐式创建新会话。
- 会话名称可修改；默认标题可来自第一条用户消息，避免额外模型请求。
- 每个会话保存独立草稿，切换后可恢复。
- 首期运行期间禁止切换和新建，并给出原因；后续是否允许后台运行会话另行评估。
- 恢复会话失败时保留现有会话和草稿，不留下不可用的半初始化状态。

### 4.2 消息与阅读

- 文本、代码、thinking、工具调用和工具结果分别呈现。
- Markdown 支持代码块、列表、表格和链接；默认不执行原始 HTML；围栏代码按语言做语法高亮。
- Thinking 默认折叠，不与最终回答混成一段正文。
- 工具卡片标题至少显示工具名、关键目标、状态；按 toolCallId 关联调用和结果。
- 参数、输出、错误、耗时在展开后查看；未知工具使用通用 renderer，不能直接丢失内容。
- `bash` 显示命令和输出；`read` 显示路径；`edit` 优先展示可用 diff；搜索显示结果摘要。
- 长输出显示截断提示，并可展开或复制；错误摘要保持可见。
- 工具结果与对话消息中的 image part 直接渲染为图片；图片数据来自已有快照，不再折叠成占位文本。
- 流式更新不重建整段对话，保留文字选择、卡片展开和滚动位置。
- 只有接近底部时自动跟随；向上阅读时保持当前位置，不再自动跟随。

### 4.3 输入与任务控制

- 建议默认 Enter 换行，Ctrl/Cmd + Enter 发送；快捷键通过配置表管理。
- 输入法正在组合文字时不能意外提交。
- 提交后立即显示“提交中”；服务端确认接收后再清除草稿。
- 请求失败时恢复可编辑状态并保留原文。网络结果不明确时先同步状态，避免重发同一任务。
- 运行期间仍可编辑下一条消息；Ctrl/Cmd + Enter 或发送按钮提交后在当前任务结束后执行（follow-up）。输入栏为空时只显示停止按钮。
- 停止后显示“停止中”，等待 agent 实际结束后再允许下一次提交。

### 4.4 状态与反馈

| 场景 | 页面表现 | 可用操作 |
| --- | --- | --- |
| 初始化 | 显示加载状态 | 等待；失败时重试 |
| 空会话 | 简短工作目录提示，聚焦输入 | 输入、新建、恢复 |
| 提交中 | 输入保留，防止重复提交 | 等待确认 |
| 生成中 | 流式正文、当前活动摘要 | 编辑草稿、停止 |
| 工具运行 | 工具卡片显示运行状态 | 查看输出、停止 |
| 停止中 | 明确显示取消请求已发出 | 等待结束 |
| 自动重试或压缩 | 显示实际阶段和简短原因 | 按底层能力取消 |
| 断线重连 | 显示连接状态，保留已显示内容 | 保留草稿；重连后同步 |
| 任务失败 | 错误与对应消息或工具关联 | 查看详情、修正后重试 |
| 未配置模型 | 显示可执行的配置说明 | 完成配置后重试 |

连接状态与 agent 状态必须分开：浏览器断线不能被当成任务结束。

### 4.5 模型与上下文

- 输入区附近显示当前模型和 thinking level，空闲时可切换。
- 正在运行时不改变本轮模型，明确禁用或说明生效时机。
- token、成本、上下文用量放在轻量状态区或详情中，不占据主标题。
- 指标来自真实运行数据；缺失时显示未知，不显示伪造的零值。

## 5. 设计评审与决策记录

### 5.1 实现技术决策

- Web UI 采用 Svelte + Vite，代码拆分为会话导航、时间线、工具卡片、右侧检查栏和输入区；页面不包含固定演示数据。
- 选择理由：当前 Web UI 是本地单用户 SPA，组件状态和条件渲染已经超过适合手写 DOM 的范围；Svelte 可以保持较小的运行时和清晰的状态边界。
- 服务端仍由 Node HTTP 服务提供 API 和 SSE，开发模式通过 Vite middleware 在同一端口提供页面；浏览器不会建立第二套 agent loop。
- 真实数据通过服务端 API 和 SSE 快照接入；视觉结构参考 `ref.png`，不以静态内容替代真实 session。

后续只需根据真实 session 使用反馈调整布局密度、颜色 token 和检查栏细节。实现约束与阶段验收统一记录在开发路线中。
